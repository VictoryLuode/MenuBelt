Custom Modular Menu (CMM)

Build your own multi-list action menus and reach them from three places at once: the cursor, the Tools menu, and a dockable panel.

Features

  • Multiple lists — e.g. "Canvas Assist", "Layers", "Add Layer", "View". Every list is fully yours to build.
  • Reuses native Krita actions — each item is a real Krita action, so icons, enable/disable state and shortcut hints are inherited automatically.
  • Nested submenus — add a menu inside a menu (any depth), each holding its own commands and further submenus, for modular organisation.
  • Custom names — rename any item to whatever you like; the menu, Tools submenu and Docker all show your name (with the native icon and behaviour).
  • Three synced entries: a cursor popup menu, Tools > Custom Modular Menu, and a Docker panel.
  • Configurable shortcuts — bind a hotkey for the whole menu or per list, right inside the editor (no need for Krita's Keyboard Shortcuts dialog).

Install / enable

  1. Copy the pykrita/ and actions/ folders into your Krita resource directory, then restart Krita.
  2. In Settings > Configure Krita > Python Plugin Manager, tick Custom Modular Menu, then restart.

Usage

  • Edit lists: Tools > Custom Modular Menu > Edit Custom List, or the Docker panel's Edit… button.
  • Custom names: in the editor, double-click a command item to give it a custom name; leave empty to use Krita’s default.
  • Submenus: press Add Submenu to nest a menu, then double-click it to enter; use the breadcrumb at the top to go back. Dragging reorders items (and submenus) anywhere.
  • Shortcuts: in the editor, click the Popup shortcut field and press a key combination (e.g. Ctrl+Alt+1) to pop that list at the cursor. The whole-menu popup is bound in Settings > Configure Krita > Keyboard Shortcuts > Custom Modular Menu > Pop Up Custom List.
  • Docker panel: Settings > Dockers > Custom Modular Menu — dock or float it like a toolbar.
Tip: prefer modifier+key combos (Ctrl/Alt/Shift + a key) and avoid shortcuts already used by Krita actions, or they won't fire.

Technical notes

  • Shortcuts use an app-level key event filter (not QShortcut), which is reliable inside Krita.
  • The action catalog is enumerated at runtime with Krita.instance().actions(), so you can pick any action.
  • Your list configuration is stored in config.json inside the plugin folder (not tracked by git).
